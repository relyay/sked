# Sked — архитектура

## Слои

```
┌──────────────────────┐   HTTP/JSON (ETag, 304)   ┌──────────────────────────┐   conditional GET   ┌────────────────────┐
│ iOS-клиент (SwiftUI) │ ────────────────────────▶ │ vksitd (Go)              │ ──────────────────▶ │ rasp.vksit.ru      │
│  • профиль (локально)│                           │  updater: тик 2 мин      │   ETag / IMS /      │  npo.pdf, spo.pdf  │
│  • кэш снимков       │ ◀──────────────────────── │  pdfx → parser → store   │   sha256 тела       └────────────────────┘
│  • «ближайшая пара»  │                           │  api: /health /schedule… │
└──────────────────────┘                           │  data/*.json + overrides │
                                                   └──────────────────────────┘
```

PDF разбирает только сервер. Клиент к rasp.vksit.ru не обращается.

## Что показал анализ реальных PDF (23.10.2026)

| Факт | Следствие |
|---|---|
| `npo.pdf` в заголовке «2 КОРПУС», `spo.pdf` — «1 КОРПУС» | номер корпуса берётся **из заголовка страницы**, а не из имени файла |
| 11 из 36 групп ходят в оба корпуса в разные дни (ИСП-225ис: пт/пн — корпус 1, сб — корпус 2) | корпус хранится у каждой пары (`Lesson.building`), а не в профиле; клиент запрашивает расписание по группе сразу из обоих PDF |
| 1 страница = 1 день, в файле окно ближайших дней (23, 24, 26) | сервер хранит прошедшие дни ещё 14 дней, а дни из нового PDF заменяют сохранённые |
| Excel → ABBYY, текстовый слой с ToUnicode | OCR не нужен |
| Текст вылезает в соседние пустые ячейки, общая пара — объединённая ячейка | сетку восстанавливаем **по линиям таблицы**, текст относим к ячейке по точке начала (`Tm`) |
| Ячейки объединяются и по вертикали (экзамен на весь день) | `Lesson.pairTo` |
| Дистант = «Д» в колонке «Ауд.» | `isRemote: true`, `room` пустой |
| В субботу 24.10 время пар **не указано** | время берётся из сетки звонков других дней того же PDF, `timeSource: "bells"` ; очные пары сдвигаются по «Занятия начинаются с …», `timeSource: "startsAt"` |
| «Занятия начинаются с 11:10», «Обед 10:55-11:20», «Обед с 11:25 до 11:50» относятся к ячейке группы, часто разбиты на фрагменты | `notes[]` у `GroupDay` |
| У НПО своя сетка звонков (9:00-10:30, 10:40-12:40, …) | время пары всегда берём из строки PDF |
| Группа `ИСП-324а`: первая цифра номера — курс | `course = 3` |

## Парсер

1. `internal/pdfx` — собственный интерпретатор content stream поверх `ledongthuc/pdf` (из неё берём только чтение объектов и ToUnicode). Возвращает фрагменты текста `{x, y, size, text}` (один `Tj`/`TJ`) и отрезки линий (`m/l/S` и тонкие `re f`), ось Y направлена вниз.
2. `internal/parser`:
   - заголовок `на DD.MM.YYYY г. (день) N КОРПУС` → дата и корпус;
   - блоки начинаются строкой «Группа:», у каждой группы две колонки подгрупп;
   - строки пар: номер пары в левой колонке, границы — горизонтальные линии;
   - сетка «пары × колонки подгрупп» объединяется (union-find) там, где граница отсутствует (≥60 % длины). Если ячейка накрывает обе подгруппы, это пара всей группы; если одну — пара подгруппы;
   - классификация текста ячейки: аудитория (`23/1`, `СЗ/1`, `ауд.114/1`, `11 цех`), «Д», преподаватель (`Фамилия И.О.` с возможным хвостом «с 8:30»), примечания, предмет (всё остальное).
3. Нераспознанное попадает в `Result.Warnings`: логируется, отдаётся в `/health` (`warnings`) и сохраняется в снимке.
4. Ручной оверрайд `data/overrides/<npo|spo>.json` целиком заменяет день группы и имеет приоритет над парсером. Перечитывается на каждом тике.

## Модель данных

```jsonc
// Lesson
{ "pair": 1, "building": 2, "pairTo": 6,            // pairTo — только для объединённых по вертикали ячеек
  "start": "08:30", "end": "10:00",  // Europe/Moscow
  "subject": "ОСиС", "teacher": "Петров С.И.", "room": "17/1",
  "isRemote": false,
  "subgroup": 1,                     // 1 | 2; поле отсутствует — пара всей группы
  "note": "с 8:30",
  "timeSource": "bells" }            // нет в PDF: "bells" | "startsAt"; поле отсутствует — время из PDF

// Note
{ "kind": "startsAt" | "lunch" | "other", "text": "Обед 10:55-11:20",
  "time": "10:55", "endTime": "11:20", "pair": 3, "subgroup": 1 }

// GroupDay
{ "group": "ИСП-225а", "lessons": [Lesson], "notes": [Note] }

// Day
{ "date": "2026-10-23", "weekday": "пятница", "building": 1, "groups": [GroupDay] }
```

Как клиент склеивает подгруппы: для подгруппы N показываются пары без `subgroup` и с `subgroup == N`. Если подгруппа «не указана», показываются все пары с бейджами.

## API

Все ответы — JSON. Для `/schedule`, `/groups` и `/buildings` сервер отдаёт `ETag` (хэш тела), `Last-Modified` (время парса) и `Cache-Control: no-cache`, а на `If-None-Match` отвечает `304`. Ошибки приходят в виде `{"error": "..."}`.

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/health` | `200 {status: ok\|degraded, version, lastParse, sources: [{source, building, lastCheck, lastSuccess, lastChange, lastError, days, warnings}]}` |
| GET | `/buildings` | `{buildings: [{building, source, parsedAt, sourceModified}]}` |
| GET | `/schedule?group=ИСП-225а[&building=1][&date=YYYY-MM-DD]` | `{group?, building?, parsedAt, sourceModified, days: [Day]}`. Без `building` дни обоих корпусов объединяются по дате, корпус указан у каждой пары. Нужен хотя бы один из параметров `group` или `building`. День остаётся в ответе с `groups: []`, если у группы в этот день пар нет |
| GET | `/groups[?building=1]` | `{groups: [{name, course, buildings: [1, 2]}]}` (сортировка: курс, затем имя) |

Коды ответов: `400` — неверный `building`/`date`; `404` — неизвестный корпус; `503` + `Retry-After` — ещё ничего не распарсено.

## iOS-клиент: решения

- **SwiftData заменён на JSON-файлы.** При сборке через xtool на Linux нет плагина макросов `SwiftDataMacros` (`@Model`), поэтому офлайн-снимок хранится как JSON в Application Support. Профиль и адрес сервера лежат в UserDefaults.
- «Сегодня» считается по `Calendar.current` с явным `TimeZone(identifier: "Europe/Moscow")`.
- Время с `timeSource` показывается как обычное. Если в день есть и дистант, и очные пары, на Главной «первая в …» заменяется на время первой очной пары («очная в 11:50»).
- Основной бандл содержит `AppResources/ru.lproj` и `en.lproj` (`resources` в `xtool.yml`). Без них iOS считает приложение англоязычным, и даты и системные элементы выходят по-английски.
- Данные обновляются при запуске, при возврате в приложение, каждые 5 минут, по pull-to-refresh и по кнопке «Обновить сейчас». При ошибке сети показывается кэш с баннером «Показаны данные от …». Если кэша нет, показывается экран ошибки с кнопкой «Повторить».
- Адрес сервера зашит: `https://lunars.ru` (`Server.production`). Настройки сервера в приложении нет, исключений ATS нет. Только UI-тесты подменяют адрес через переменную окружения `SKED_SERVER_URL`. Сервер в продакшене должен стоять за reverse proxy с TLS (nginx или Caddy → `skedd` на :1984).

## Чек-лист приёмки

**Сервер**
- [x] `go test ./...` проходит, нераспознанных ячеек в `testdata/*.pdf` нет.
- [x] Повторная проверка неизменённого PDF не запускает разбор заново (304 / тот же sha256).
- [x] Если источник недоступен, отдаётся последний снимок, а `/health` показывает `degraded` с текстом ошибки.
- [x] `If-None-Match` → 304.
- [x] Ручного обновления (`/admin/refresh`) нет: расписание обновляется только тикером раз в 2 минуты.

**Онбординг**
- [ ] Первый запуск открывает один экран: ФИО → группа (список с поиском по курсам) → подгруппа. Корпус и курс не спрашиваются.
- [ ] Кнопка «Сохранить» недоступна без группы; при пустом ФИО появляется подсказка и фокус уходит в поле.
- [ ] Группы приходят с `/groups`.
- [ ] Если сервер недоступен, показывается понятное сообщение и кнопка «Повторить»; адрес сервера можно поменять прямо с этого экрана.
- [ ] После сохранения сразу открывается Главная.

**Главная**
- [ ] Карточка «Следующая пара» в формате «N пара · предмет · время · корпус, каб.» и с таймером «начнётся через …», который обновляется раз в минуту.
- [ ] Во время пары написано «сейчас идёт», после последней пары — «На сегодня пар больше нет — отдыхай 🎉».
- [ ] Карточка следующего учебного дня в формате «Завтра (сб) · N пар · корпус · первая в …», корпус берётся из пар этого дня; если завтра свободно, есть строка «Завтра пар нет».
- [ ] Во время загрузки видны скелетоны; офлайн с кэшем — баннер «Показаны данные от …»; без кэша — «Повторить».

**Расписание**
- [ ] Переключатель День/Неделя.
- [ ] Чипы дат начинаются с сегодняшнего дня и идут до конца PDF; заголовок «Пятница, 23 октября · сегодня · корпус 2».
- [ ] На сегодняшнем дне есть подсказка «Следующая · N пара · через …».
- [ ] Пары другой подгруппы не показываются, выделения своей подгруппы нет, бейджа подгруппы у пар нет; у дистанта написано «дистант · преподаватель», кабинета нет; время показывается без «≈».
- [ ] Под заголовком дня (и в шапке дня в недельном виде) показываются «Занятия начинаются с …» и обеды из PDF для своей подгруппы.
- [ ] В дне сначала название пары, потом время; в неделе номер пары в кружке, затем название, время «начало – конец», кабинет.
- [ ] На пустом дне — «Пар нет» с иконкой.

**Профиль**
- [ ] Сверху карточка пользователя (инициалы, ФИО, группа · курс, подгруппа обычным текстом); по стрелке открывается экран с ФИО, группой и подгруппой.
- [ ] Ниже секции «Данные» и «О приложении», а в самом низу «Сбросить профиль» с подтверждением. Настройки сервера нет.
- [ ] Видны «Данные обновлены: …», кнопка «Обновить сейчас» и версия приложения.

**Общее**
- [ ] Светлая и тёмная темы, Dynamic Type до AX5 без обрезки текста, VoiceOver читает карточки целиком.
- [ ] Язык устройства ru или en переключает все строки.

## Запуск

```sh
cd server
go run ./cmd/skedd                                  # слушает 0.0.0.0:1984, данные в ./data
go run ./cmd/skedd -addr 192.168.1.246:1984 -interval 2m -data /var/lib/sked
go test ./...                                       # парсер на реальных PDF + интеграционные
go run ./cmd/parsepdf testdata/spo.pdf              # отладка парсера
```

```sh
just server                    # → dist/skedd
just ios                       # → dist/Sked.ipa
cd ios
SKED_CORE_ONLY=1 swift test   # логика клиента на Linux
xtool dev build                # сборка .app
xtool dev                      # сборка и установка на подключённый iPhone
```

Env: `SKED_ADDR`, `SKED_DATA`, `SKED_NPO_URL`, `SKED_SPO_URL`, `SKED_DEBUG`.

### Docker

```sh
docker compose up -d --build        # сборка server/Dockerfile и запуск на :1984
docker compose logs -f sked
```

Снимки и `overrides/` лежат в `./data` на хосте. Контейнер работает от `SKED_UID:SKED_GID` (по умолчанию 1000:1000), чтобы файлы в `./data` оставались твоими. Остальные переменные: `SKED_PORT` (порт на хосте), `SKED_VERSION` (версия в `/health`), `SKED_DEBUG`. Healthcheck вызывает `/skedd -healthcheck`. С rootless podman вместо `user:` используй `--userns=keep-id`.
